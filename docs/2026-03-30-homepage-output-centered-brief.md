# Homepage Brief: Output-Centered Acquisition Page

Generated on 2026-03-30
Branch: feat/phase1-mvp
Scope: Landing page positioning and image direction only

## Problem

当前首页有两个偏差：

- 首屏在用前端拼一个“像产品图”的假预览，质感不对。
- 文案把产品说成“模块化货架”，范围太窄。

这次首页不该继续强调“工具很专业”，而该强调一个更直接的结果：

甲方设计可以更快做出一个简易 3D 结构方案，让施工方一眼看懂结构关系。

## User

核心用户不是泛泛的“客户”，而是：

- 甲方设计

当前链路：

1. 甲方提出需求
2. 甲方设计自己用专业工具画图
3. 画图过程麻烦
4. 图发给施工方后，结构关系还是可能讲不清

核心痛点：

- 想法能描述，图却难画
- 专业工具太重，出一个简模也慢
- 自己想要的样子，别人不一定能理解

## Product Promise

第一版卖点不是“专业建模能力”，而是：

- 快速展示你的模块化设计方案

更准确地说，是：

- 更快把想法变成可沟通的结构方案图

## Positioning

首页定位统一为：

- 模块化设计平台

不再把“货架”当成产品唯一身份。

货架可以作为示例，但不应成为整页叙事中心。

## Chosen Direction

采用“输出物优先”的首页结构，而不是“工具能力优先”。

页面第一眼就让人看到最后能产出的东西：

- 结构总览图
- 关键模块关系
- 适合发给施工方沟通的方案感

## Recommended Page Structure

### 1. Hero

- Eyebrow: 模块化设计平台
- Title: 模块化设计平台
- Subtitle: 快速展示你的模块化设计方案
- Visual: 一张真实、干净、完整的模块化结构主图

补充说明不要太多，首屏只做一件事：

- 让人马上知道这不是 CAD，不是假海报，而是一个能快速产出方案图的工具

### 2. Problem Strip

用三句短话说清旧方式的问题：

- 想法能描述，图却难画
- 专业工具太重，出简模也慢
- 发给施工方，结构关系还是容易讲不清

### 3. Output Proof

用 3 张真实图片证明首页承诺：

- 结构总览
- 模块关系
- 沟通更直接

这里不要用前端绘图，不要用假 3D 卡片。

### 4. CTA

- Heading: 先把方案展示出来
- Body: 用更轻量的方式做出简模，方便继续沟通与落地
- CTA: 开始设计

## Image Rules

所有首页图片遵守这几个原则：

- 只生成干净底图，不在 AI 图里直接生成中文标题、箭头、尺寸和 UI
- 先保证整套图片是同一个产品、同一种材质、同一种光线语言
- 先讲结构关系，再讲场景氛围
- 不要做成传统卖场广告大片
- 不要过度强调“货架”，保持“模块化结构系统”的泛化感

## Deliverable

这一版首页真正要卖的交付物是：

- 一张结构总览图 + 关键模块标记

如果施工方看到图还是需要靠大量解释，那这版视觉就还没有打中。

## Open Questions

- 关键模块标记是后期做进图里，还是后面在页面里叠加
- 是否要在首屏下方补一句“适用于货架、陈列、收纳等模块化方案”
- context 图是否放首页，还是留到案例区

## Assignment

先生成一套一致的 4 张图，再找一个真实会看这类方案的人做快速判断：

- 哪一张最像“可以直接发给施工方”的方案图

如果对方犹豫，说明图还偏装饰，不够像输出物。
