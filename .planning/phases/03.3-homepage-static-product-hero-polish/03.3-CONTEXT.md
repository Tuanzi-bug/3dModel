# Phase 3.3: Homepage Static Product Hero Polish - Context

**Gathered:** 2026-03-30
**Status:** Ready for planning

<domain>
## Phase Boundary

Phase 3.3 is a focused correction pass on the homepage after the first 3D-preview implementation landed but did not match the desired visual quality. This phase resets the landing hero around a static, product-led preview that feels closer to a real product page or product-photography surface. The goal is not to expand homepage functionality, redesign the whole site, or continue polishing live 3D interaction. The success condition is a more credible, more restrained, more product-oriented first screen.

This phase may apply minimal cleanup to the first section below the hero if that content visually conflicts with the new direction, but it must not turn into a full-homepage redesign. Future live 3D work stays deferred unless it can satisfy the same realism brief.

</domain>

<decisions>
## Implementation Decisions

### Product and UX guardrails
- **D-01:** Avoid overdesign; user experience, credibility, and clarity take precedence over novelty.
- **D-02:** Static presentation is the current priority; dynamic 3D is not the primary deliverable for this phase.
- **D-03:** The homepage should feel like a believable product page, not an animation demo, game asset viewer, or stylized 3D toy showcase.
- **D-04:** If existing live-3D code remains in the homepage path, it should be disabled, commented out, or clearly deprioritized so the static hero becomes the main experience.
- **D-05:** This phase may minimally harmonize the first section below the hero, but must not expand into a full-homepage or multi-page redesign.
- **D-06:** Phase 4 mini-program work remains deferred until this static homepage polish is complete.

### Hero composition
- **D-07:** The hero stays single-column rather than splitting into a left-right marketing layout.
- **D-08:** Title, supporting copy, and CTA sit above the preview image, not overlaid on top of it.
- **D-09:** The preview area is one large static product image or image-like surface, not a visible "3D window" or interactive viewer frame.
- **D-10:** A small set of parameter labels should appear in the preview’s lower-right area.
- **D-11:** Those labels should mix product-facing value signals with professional specification-style information.
- **D-12:** The preview should remain the visual center of the first screen, while copy remains immediately readable and subordinate to the product presentation.

### Realism brief
- **D-13:** The preview must move away from animation energy, toy-like form language, and stylized rendering cues.
- **D-14:** The target look is realistic product preview / studio product photography / industrial design render.
- **D-15:** Lighting should imply studio conditions with distinct key, fill, and subtle rim separation instead of flat, evenly lit demo lighting.
- **D-16:** Shadows should feel grounded and believable, including stronger contact shadow and overall depth cues.
- **D-17:** Materials must differentiate clearly; surfaces should not all read as the same plastic-like material.
- **D-18:** Saturation should be restrained, highlights controlled, and the environment kept neutral.
- **D-19:** The camera should feel product-photography-like rather than dramatic or exaggerated.
- **D-20:** Subtle realism helpers are acceptable, but the output must avoid looking filtered, glossy-for-the-sake-of-gloss, or overprocessed.

### Visual language and content
- **D-21:** The hero should lean product-oriented rather than editor-oriented.
- **D-22:** The preview should imply a real modular shelf product with believable frame, shelf, and material relationships.
- **D-23:** The surrounding page should become quieter where needed so the hero’s new realism does not clash with generic landing-page promo styling.
- **D-24:** The section immediately below the hero may be simplified, de-noised, or rewritten in a more product-credible tone if necessary.

### the agent's Discretion
- Exact source of the static preview image/render, as long as it aligns with the realism brief and the repo’s practical constraints.
- Exact chip text and sequence, as long as chips stay sparse and believable.
- Exact hero copy wording, as long as it stays Chinese, product-led, and restrained.
- Exact spacing, background tone, and card treatment, as long as the result reads as realistic and premium rather than overdesigned.

</decisions>

<specifics>
## Specific Ideas

- The chosen first-screen structure is: navigation → title/subtitle/CTA → large static preview.
- No left-right hero split.
- The large preview image should feel like a product main image.
- Parameter tags sit at the lower-right of the preview and stay restrained.
- The approved design direction is "simple, product-oriented, realistic, and page-like."
- The explicit negative direction is "animation-like, cartoonish, toy-like, overly saturated, plastic-looking, or generic 3D-demo energy."
- The immediate follow-up work after the hero itself is only minimal harmony cleanup for the first section below it.

</specifics>
