# Phase 2.1: Freeform Stability & Preview Polish - Context

**Gathered:** 2026-03-30
**Status:** Ready for planning
**Source:** User bug report during `$gsd-plan-phase bug: ...`

<domain>
## Phase Boundary

Phase 2.1 is an inserted hardening phase between the completed freeform-builder work and the planned precision/output work. Its job is not to add new product scope. Its job is to remove the regressions and polish gaps that appeared immediately after Phase 2 shipped: duplicate/edit continuity, component-library support boundaries, viewport gizmo crash safety, and preview fidelity.

</domain>

<decisions>
## Implementation Decisions

### Duplicate continuity
- Duplicating a component must keep the duplicate immediately editable in the properties panel.
- Duplicate IDs must remain compatible with the editor's typed `type-sequence` contract so labels, counters, and follow-up edits do not drift.

### Component library scope
- Unsupported component-library entries must not behave like working actions.
- For now, only the first two component types in the current library, `杆` and `层板`, are considered user-approved interactive entries.
- Remaining entries may stay visible, but they must be clearly disabled and non-clickable until they are actually supported.

### Viewport stability
- Clicking the bottom-right coordinate-axis gizmo must not throw runtime errors.
- Camera-control integration must survive null/unmounted control references and selection changes safely.

### Preview fidelity
- Dashboard preview images should move from the current pseudo-isometric projection to a stable x-axis-oriented view.
- Preview generation must stay deterministic from canonical `sceneGraph` data rather than adding a manual image-management path.
- The revised preview should be visually closer to the real shelf structure, even if it remains a lightweight SVG abstraction.

### Workflow constraints
- User-facing copy remains Chinese.
- Project commands, tests, and builds must continue running inside Docker containers rather than polluting the host environment.
- Phase 2.1 should stay narrowly scoped to these regressions and should not absorb Phase 3 snapping/output features.

### The agent's Discretion
- Exact disabled-state copy and visual treatment for unsupported components.
- Exact duplication implementation shape, as long as typed IDs, selection continuity, and editability are guaranteed.
- Exact x-axis preview art style, as long as it is deterministic and more faithful than the current projection.

</decisions>

<specifics>
## Specific Ideas

- The runtime error strings to eliminate are:
  - `Cannot use 'in' operator to search for 'getTarget' in null`
  - `Cannot use 'in' operator to search for 'minPolarAngle' in null`
- The duplicate regression likely spans both ID generation and selection continuity, so the fix should treat those as one contract.
- Preview fidelity should prioritize recognizability from the side profile over decorative perspective effects.

</specifics>
