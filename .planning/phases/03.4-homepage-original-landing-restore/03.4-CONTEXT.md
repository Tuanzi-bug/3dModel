# Phase 3.4: Homepage Original Landing Restore - Context

**Gathered:** 2026-03-30
**Status:** Ready for planning

<domain>
## Phase Boundary

Phase 3.4 is a deliberate homepage rollback. The user does not want the current Phase 3.3 static product-hero direction and instead wants the homepage restored to the original landing-page baseline that shipped in commit `42a3af0`.

This is not a new redesign, not another hero polish pass, and not a continuation of the 3.2 or 3.3 homepage experiments. The phase should restore the original hero copy, CTA hierarchy, simple placeholder preview block, feature-card copy, CTA section, and footer behavior closely enough that the homepage again feels like the initial simple page the user preferred.

Scope must stay limited to the homepage route and landing-specific tests/components. Do not reopen editor, dashboard, auth, or Phase 4 mini-program work.

</domain>

<decisions>
## Implementation Decisions

### Baseline choice
- **D-01:** "Restore the homepage to the original page" means the landing page as committed in `42a3af0`.
- **D-02:** The restore target is the original simple homepage, not the Phase 3.2 interactive hero and not the Phase 3.3 static product-preview hero.

### Hero restore contract
- **D-03:** Restore the original hero headline: `专业的 3D 模块化货架设计工具`.
- **D-04:** Restore the original supporting copy: `实时 3D 可视化，所见即所得。选择模板，调整尺寸，立即预览你的设计效果。`
- **D-05:** Restore the original centered CTA row with `开始设计` and `查看示例`.
- **D-06:** Restore the simple preview placeholder block with the centered icon and text `3D 预览区域`.
- **D-07:** The homepage route should no longer render `HeroPreview`, `HeroPreviewPoster`, or `HeroPreviewScene`.

### Below-the-fold restore contract
- **D-08:** Restore the original three feature cards and their baseline copy:
  - `实时 3D 可视化`
  - `丰富的模板库`
  - `快速导出`
- **D-09:** Keep the original CTA section and footer wording from the initial page unless a technical constraint requires an exact-text preservation note in the plan.

### Testing and scope
- **D-10:** Replace or rewrite homepage tests so they lock the restored baseline rather than asserting the superseded Phase 3.2 or 3.3 hero contracts.
- **D-11:** The rollback stays scoped to landing-page files and tests; no unrelated product-surface cleanup should hitchhike into this phase.

### the agent's Discretion
- Whether unused `HeroPreview*` files are deleted or simply removed from the homepage route, as long as the route no longer depends on them and tests stay coherent.
- Whether homepage coverage is best expressed through route tests only or a mix of route/component/browser checks, as long as the restored baseline is verifiable.
- Minor class-name normalization is allowed if it preserves the original structure, copy, and user-visible behavior.

</decisions>

<specifics>
## Specific Ideas

- Use commit `42a3af0` as the restoration baseline for homepage copy and structure.
- The restored hero is centered and text-first, with the preview as a simple placeholder block below the CTA.
- The original homepage did not have parameter chips, live-scene hinting, or product-photo styling. Those must not survive in the final contract.
- The restore should reintroduce the simpler feature-card language about real-time 3D visualization, template variety, and export speed.

</specifics>
