# Phase 3.2: Homepage 3D Preview & Web Adaptation - Context

**Gathered:** 2026-03-30
**Status:** Updated after homepage visual-direction reset

<domain>
## Phase Boundary

Phase 3.2 remains a narrow inserted homepage phase before the mini-program work begins, but the implementation direction has changed. The immediate priority is no longer "prove a live 3D hero interaction"; it is to make the landing-page hero feel like a credible, polished product page. The homepage should first ship a strong static experience that looks closer to a real product page or product preview surface, not an animation demo, toy render, or game asset showcase.

Dynamic 3D is no longer the current design target. If any live 3D code remains in the implementation, it should be treated as temporarily disabled or commented out until the static hero composition, preview realism, and page quality are approved. Broader web adaptation is still not part of this phase, and Phase 4 mini-program work remains deferred.

</domain>

<decisions>
## Implementation Decisions

### Product and UX guardrails
- **D-01:** The homepage hero should optimize for user experience and credibility first; the user explicitly wants to avoid overdesign.
- **D-02:** The current homepage direction should shift away from animation-first thinking and toward a more realistic product-page presentation.
- **D-03:** The priority is static-page quality before any dynamic 3D enhancement is reconsidered.
- **D-04:** If dynamic 3D code remains in the hero, it should be temporarily disabled or commented out rather than treated as the current deliverable.
- **D-05:** Broader web adaptation remains deferred and should not be folded into this revisit.
- **D-06:** Phase 4 mini-program work remains deferred until the web-side homepage experience is in a much better state.

### Homepage visual direction
- **D-07:** The homepage hero should lean toward a real product presentation instead of a concept animation or stylized 3D demo.
- **D-08:** The desired direction is a hybrid "product page" hero: product-led composition with restrained page information, not a full editor UI and not a pure abstract hero image.
- **D-09:** The visual target is "real page restoration" — the homepage should feel believable as a shipping product surface rather than a placeholder or marketing-only mock.
- **D-10:** The hero should include a strong central product preview plus a small number of supporting parameter labels to reinforce page realism.
- **D-11:** Those labels should be a mixed set: some product-selling tags and some professional/industrial specification tags.
- **D-12:** The hero should stay simple and product-oriented rather than becoming a dense dashboard, full product-detail card, or editor shell.

### Preview realism and art direction
- **D-13:** The current homepage preview should stop feeling animated, stylized, toy-like, or game-like.
- **D-14:** The target look is closer to realistic product photography, studio product render, or industrial design preview imagery.
- **D-15:** The preview should use more realistic studio-lighting logic: visible key/fill/rim separation instead of flat all-around illumination.
- **D-16:** The preview should favor stronger soft shadows, clearer contact shadows, and better ambient depth cues instead of weak or floating-looking grounding.
- **D-17:** Materials should read as believable PBR surfaces with visible roughness and metalness differences; not every surface should feel like the same glossy plastic.
- **D-18:** Surface color should be less saturated and less toy-like; highlights should be controlled so the object feels premium and grounded rather than cartoonish.
- **D-19:** The backdrop should be neutral and restrained, closer to a studio or clean product-photography environment than a dramatic animated stage.
- **D-20:** Camera framing should feel like product photography: credible perspective, clear volume, and no exaggerated wide-angle distortion.
- **D-21:** Subtle realism enhancers are acceptable, such as restrained tone mapping, anti-aliasing, ambient occlusion, soft depth cues, and light reflections, but the result must not feel filter-heavy or overprocessed.

### Future dynamic-preview constraint set
- **D-22:** If live 3D is reintroduced later, it must obey the same realism brief: photorealistic, realistic product preview, studio lighting, soft shadow, contact shadow, ambient occlusion, realistic PBR materials, subtle reflections, and neutral background.
- **D-23:** If live 3D returns later, it must explicitly avoid cartoonish, toy-like, overly saturated, flat-lit, plastic-looking, stylized, or game-asset-preview results.
- **D-24:** Dynamic motion is not the success metric; believable product presentation is the success metric.

### the agent's Discretion
- Exact hero copy rewrite and supporting microcopy, as long as it remains Chinese and product-oriented.
- Exact visual arrangement of mixed parameter tags, as long as they stay sparse and believable.
- Exact static-composition approach used to represent the product preview, as long as it moves the result toward a realistic product-page feel and away from an animated demo look.
- Exact neutral background tone, lighting warmth/coolness, and visual hierarchy, as long as the final page reads as realistic, restrained, and premium.

</decisions>
