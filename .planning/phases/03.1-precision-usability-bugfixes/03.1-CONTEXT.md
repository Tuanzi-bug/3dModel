# Phase 3.1: Precision Usability Bugfixes - Context

**Gathered:** 2026-03-30
**Status:** Ready for planning

<domain>
## Phase Boundary

Phase 3.1 is an inserted bugfix phase between Phase 3 and Phase 4. It does not add new product capabilities. It only fixes three post-Phase-3 regressions in the existing editor: over-aggressive movement snapping, garbled BOM CSV export when opened in Excel, and camera usability problems around deselection, focusing, and zoom controls.

</domain>

<decisions>
## Implementation Decisions

### Snapping behavior
- **D-01:** Dragging should stay smooth during movement; snapping should resolve when the drag is released, not on every transform frame.
- **D-02:** On release, snapping should try compatible component-to-component anchors first and fall back to grid snapping only if no component anchor match is found.

### CSV export compatibility
- **D-03:** BOM export remains a standard `.csv`, not `.xlsx` and not a custom text format.
- **D-04:** The CSV must stay comma-delimited and must open correctly in Excel with Chinese text intact.

### Viewport focus and zoom
- **D-05:** Clicking empty space should only clear selection; it must not reposition the camera or zoom the scene.
- **D-06:** The viewport should add explicit toolbar actions for `聚焦选中`, `放大`, and `缩小`.

### the agent's Discretion
- Exact snap-release event wiring between `TransformControls`, store updates, and snap resolution.
- Exact component-anchor threshold tuning, as long as the drag feel improves and anchor-first fallback-to-grid behavior is preserved.
- Exact CSV compatibility technique, as long as the exported file remains a comma-delimited CSV and opens cleanly in Excel.
- Exact zoom step size and what the focus button does when no component is selected.

</decisions>

<code_context>
## Existing Code Insights

### Reusable Assets
- `resolveSnapPosition` in `packages/core/src/utils/snap.ts`: already centralizes anchor/grid snap math and should remain the canonical resolver.
- `generateBom` and `serializeBomCsv` in `packages/core/src/utils/bom.ts`: already keep export content derived from `sceneGraph`.
- `getSceneBounds` in `packages/core/src/utils/scene-bounds.ts`: available for focus-to-selection framing without inventing parallel camera math.
- `ViewPresetToolbar` and `DimensionOverlay`: establish the current viewport-chrome pattern for adding more controls.

### Established Patterns
- Precision logic belongs in `packages/core`, while `packages/web` should stay a thin integration layer.
- Editor interactions persist through the Zustand store and canonical `sceneGraph`, not local canvas-only state.
- User-facing copy stays Chinese and follows the existing editor chrome instead of introducing a new panel or page.
- Project build/test/runtime verification still runs in Docker; git operations run on the host.

### Integration Points
- `ViewportCanvas` is the integration point for release-time snapping, empty-space deselection behavior, and explicit focus/zoom controls.
- `Header` is the integration point for export compatibility fixes because the BOM action already lives there.
- `precision-tools.spec.ts` is the right browser-level regression to extend because it already exercises snapping, viewport controls, and export in one flow.

</code_context>

<specifics>
## Specific Ideas

- The desired movement feel is "drag manually, snap precisely when letting go", not magnetic movement on every frame.
- The export fix is specifically about Excel opening the CSV correctly; the file should not be replaced with `.xlsx`.
- Empty-space clicks should be boring: deselect only.
- Focus and zoom should be explicit viewport buttons, not hidden gestures.

</specifics>
